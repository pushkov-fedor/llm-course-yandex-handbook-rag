# План проекта: RAG-поисковик по учебнику ML (Яндекс)

## Этап 1. Сбор и подготовка данных
Цель: подготовить качественную базу знаний.

- Спарсить учебник (HTML / PDF → текст)
- Очистить текст от мусора
- Нарезать текст на чанки **по токенам** с помощью токенайзера Mistral  
  (≈800 токенов, overlap 10–15%)
- Добавить метаданные: глава, раздел, источник
- Сохранить чанки в структурированном виде (jsonl)

Результат: готовая текстовая база для поиска и индексации.

---

## Этап 2. Простой RAG (baseline)
Цель: получить рабочий RAG без усложнений.

- Посчитать embeddings для всех чанков
- Построить FAISS-индекс
- Для вопроса пользователя:
  - embedding вопроса
  - поиск top-k чанков
  - один проход LLM: вопрос + найденный контекст
- Ответ строго на основе контекста + ссылки на источники
- Простой интерфейс (CLI или Streamlit)

Результат: линейный RAG-пайплайн (baseline).

---

## Этап 3. Полноценный RAG с нелинейной логикой
Цель: удовлетворить формальные критерии проекта.

### Усложнение логики
- Классификация вопроса (comparison / default)
- Разные стратегии retrieval в зависимости от типа вопроса:
  - comparison: multi-query поиск (по каждой сущности отдельно) + merge + rerank
  - default: single query + rerank
- Reranking (CrossEncoder) всегда, для обоих типов
- Multi-step retrieval:
  - проверка достаточности контекста
  - повторный поиск с уточнённым запросом при необходимости
- Self-check:
  - отказ от ответа, если информация в учебнике не найдена

### Оценка качества
- Валидационный датасет вопросов
- Retrieval-метрики: Recall@k, MRR
- Answer-метрики: groundedness, correctness

Результат: адаптивная RAG-система, которую нельзя заменить простым промптингом.
